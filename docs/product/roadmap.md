# Roadmap

Each milestone ships something verifiable and ends at its exit criteria, not on a date. Later milestones are deliberately coarse and get re-planned once the previous one finishes. Detailed plans live in [`docs/plans/`](../plans/).

| Milestone | Goal | Exit criteria |
|---|---|---|
| **M0: Foundation** ✓ done | Repo, tooling, docs, decision records, dev process | `make check` passes locally and in CI. Product, architecture and ADRs are documented. No platform code. |
| **M1: Runtime core** ✓ done | Single-turn runtime: explicit state machine, versioned event log and fold, RunStore port (in-memory + SQLite), ModelProvider port with a scripted fake, resume from the log | Crash-boundary and SIGKILL recovery tests pass. Import-boundary tests enforce NFR-7. ADR-0004 and ADR-0005 accepted, ADR-0006 added. Plan: [m1-runtime-core.md](../plans/m1-runtime-core.md). |
| **M2: Universal model gateway** — implemented; live verification pending | Model gateway and deployment model (ADR-0011); protocol adapters for Anthropic Messages and OpenAI-compatible Chat Completions (ADR-0012); locality, routing policy and on-prem networking (ADR-0013); failure taxonomy, Hollis-owned retries, ambiguous-outcome policy, budgets (ADR-0007); credentials and redaction (ADR-0009); retention policy (ADR-0010). Plans: [m2-gateway.md](../plans/m2-gateway.md), [m2-anthropic.md](../plans/m2-anthropic.md). | **Met offline:** one runtime path runs local, private and external deployments over both protocols, configured by data; routing policy, capability validation and custom-CA TLS tested; secret-handling requirements 1–4 tested; the default suite needs no key or network. **Not yet met:** any live verification. The Anthropic live test and the conformance suite exist but haven't been run (no API key or local inference server here); behavioral evals need live access. |
| **M3: Tool runtime and secure action execution** — implemented; live verification pending | Durable multi-turn tool loop with policy, approval and recovery (ADR-0014); `@tool` definitions, registry, rule-based policy and approval (ADR-0015); declared execution isolation, filesystem and fixed-command tools (ADR-0016); MCP client over stdio and Streamable HTTP (ADR-0017); tool calling in both protocol adapters. Plan: [m3-tools.md](../plans/m3-tools.md). | **Met offline:** tool calls are validated, policy-checked, recorded and replay-safe; authorization, approval binding and idempotent-only re-execution are enforced by the fold; denials, approvals, crashes and hostile inputs are tested, and the key protections are mutation-checked; MCP tested in-process, over a real stdio subprocess and over loopback HTTP. **Not met:** a verified sandbox (none exists; the command tool is explicitly not one); live tool calling against any model (the opt-in test exists but hasn't run); interoperability with third-party MCP servers. The coding-agent demo was dropped from scope: the core must not assume coding tasks. |
| **Execution backends** (unscheduled) | A sandbox backend with verified isolation per platform | Escape, egress and resource-exhaustion tests pass on each supported platform before anything is labelled `sandbox` ([ADR-0016](../decisions/0016-execution-isolation.md)). |
| **M4: Context engineering and memory** — implemented; live verification pending | Context engine with token budgets, recorded plans and compaction (ADR-0018); artifact store for complete tool results (ADR-0019); governed persistent memory with slots, temporal validity and scopes (ADR-0020); SQLite FTS5 storage, hybrid lexical recall and honest deletion (ADR-0021). Plan: [m4-context-memory.md](../plans/m4-context-memory.md). | **Met offline:** context assembled from multiple sources within declared budgets; long histories compacted without altering the log (100% of actions and notes kept over 6 compactions); large results stored and selectively read; memory isolated by scope, with updates, corrections, conflicts, temporary conditions and deletion; retrieval backend chosen by evaluation (SQLite FTS5, no vector database). Memory gives clean evidence on 100% (tuned) and 91% (held-out) of probes against 25–42% for raw history at equal budget ([evaluation](../architecture/evaluation.md)). **Not met:** behavioral evals with a real model (the opt-in live evaluation hasn't run); public memory benchmarks; quality of model-assisted summarization and extraction. |
| **M5: Knowledge retrieval and RAG** — implemented; live verification pending | Embedding task in the gateway (ADR-0022); ingestion with structure and provenance (ADR-0023); SQLite hybrid retrieval with access control in the store (ADR-0024); grounding, citations, trust and deletion (ADR-0025). Plan: [m5-knowledge.md](../plans/m5-knowledge.md). | **Met offline:** mixed-format ingestion with locations and versions; atomic updates and deletion; exact, lexical and dense retrieval compared by [evaluation](../architecture/rag-evaluation.md) (default Recall@5 1.00 on both corpora, nDCG@10 0.84 vs 0.72 for M4-style lexical); access enforced before scoring; citations verified against actual evidence; poisoning and leakage security tests; M4's identifier gap closed. **Not met:** a public benchmark and any real embedding or answering model (opt-in live evaluation exists, not run). |
| **M6: Developer experience, product interface and brand** — implemented; live verification pending | The Hollis identity ([brand guide](../../brand/README.md)); workspace and one platform layer (ADR-0026); REST API with problem details, SSE and long polling, and an SDK with embedded and remote backends (ADR-0027); authentication and authorization (ADR-0028); the CLI; the web app and design system (ADR-0029); runtime cancellation, observers and run listing. Plan: [m6-product.md](../plans/m6-product.md). | **Met offline:** CLI, REST API and SDK reach parity over one service layer; the SDK runs every operation against both backends; authorization tested and mutation-checked; runs survive dropped connections, shutdown mid-call, cancellation and restart; credentials absent from stored data and responses; the web app's journeys pass in Chrome against a real server; accessibility linted and contrast measured. **Not met:** any live model behind the interfaces (the demo model is rules, not a model); TLS and external identity providers (proxy required); screen-reader testing beyond semantics and automated checks; browsers other than Chrome. |
| **M7: Multi-agent orchestration** — implemented; live verification pending | Delegation as durable child runs with recorded lineage, structured assignments and reports, and verified evidence (ADR-0030); permissions that only narrow, limits, token budgets with a coordinator reserve, cascading cancellation (ADR-0031); plans on a deterministic workflow coordinator; an A2A position (ADR-0032); orchestration in the SDK, CLI, REST API and web inspector. Plan: [m7-orchestration.md](../plans/m7-orchestration.md). | **Met offline:** parallel, dependent, hierarchical and planned delegation recorded in trajectories; recovery without duplicate children; narrowing, forged evidence, budgets and recursion tested and key checks mutation-checked; evaluated against single-agent baselines on eight scenarios, including where multi-agent loses ([evaluation](../architecture/orchestration-evaluation.md)). **Not met:** any live model as coordinator or specialist (opt-in evaluation written, not run); A2A interoperability (deferred). |
| **M8: Specialized agents and the agent ecosystem** — implemented; live verification pending | Templates and capabilities as versioned data, materialized into ordinary agents with recorded origin, customization, previewed upgrades and export; Agent Skills (ADR-0033); output contracts checked against the run's log (ADR-0034); per-run policy overlays that only tighten, inherited by delegations (ADR-0035); capability tools (code, data, docs, configured commands, read-only git) with protected paths (ADR-0036); seven first-party specialists in the SDK, CLI, REST API and web gallery. Plan: [m8-specialized-agents.md](../plans/m8-specialized-agents.md). | **Met offline:** every first-party specialist's flow runs end to end on the demo model and in every interface (including a Chrome journey); contracts reject misreported files, lines, queries, citations, verifications and steps, and the retry loop goes through the normal tool loop; overlays deny and are inherited by delegated runs; git, file, SQL and command protections have adversarial tests, and removing each git defence fails one; evaluated against generalist baselines under explicit error models, including where specialization costs more or does not help ([evaluation](../architecture/specialist-evaluation.md)). **Not met:** any live model as a specialist (opt-in evaluation written, not run); a sandbox for configured commands or skill scripts (scripts are never executed); third-party template or skill interoperability beyond the file formats. |

Deferred with no milestone: virtual workforce features, cloud deployment packaging beyond a container, model training.
